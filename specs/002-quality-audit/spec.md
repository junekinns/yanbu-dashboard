# Feature Specification: 서비스 품질 감사 — 정확성·견고성·명확성

**Feature Branch**: `002-quality-audit` (main에 직접 반영 — 001과 동일한 이유로 별도 브랜치 없음)

**Created**: 2026-09-17

**Status**: Draft

**Input**: User description: "이 서비스 품질을 전체적으로 끌어올릴 수 있는 부분이 있는지 세세하게 검토해봐. 과하게 스펙을 이것저것 끼워넣으라는 게 아니야."

**Scope rule**: 새 지표·새 화면을 추가하지 않는다. 이미 있는 지표가 (1) 사실을 정확히 말하고, (2) 한 소스가 죽어도 나머지가 살아 있고, (3) 교민 가족이 오해 없이 읽을 수 있게 만드는 것만 다룬다. 감사에서 발견된 항목의 근거는 `research.md`에 있다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 지표가 거짓말하지 않는다 (Priority: P1)

교민 사용자가 "위성 열 감지 평시" 배지를 봤을 때, 그 배지가 실제 데이터를 정직하게 요약한 것이어야 한다. 라벨이 "최근 24h"면 진짜 24시간이어야 하고, 조용하던 곳에서 갑자기 화재가 늘면 "평시"가 아니라 "주의"가 떠야 한다.

**Why this priority**: 이 대시보드의 존재 이유는 배지 하나로 상황을 읽는 것이다. 배지가 틀리면 나머지가 아무리 예뻐도 의미가 없다. 감사에서 배지 계산에 체계적 편향 2건, 경계 조건 오류 1건, 라벨-실제 불일치 1건이 확인됐다.

**Independent Test**: `fetch_data.py`를 실행한 뒤 `data/latest.json`의 값이 라벨이 주장하는 정의와 일치하는지 스크립트로 검증한다(quickstart.md 참고).

**Acceptance Scenarios**:

1. **Given** FIRMS 화점 데이터, **When** "최근 24h N건"을 계산하면, **Then** N은 현재 시각 기준 지난 24시간(acq_date+acq_time)의 화점 수이며 어제 00:00 UTC부터의 누적(24~48시간)이 아니다.
2. **Given** 평시 중앙값이 0 또는 1인 권역/지표, **When** 현재 값이 명백히 높으면(예: 화점 6건, 공지 7건), **Then** 배지는 "평시"가 아니라 "주의/위험"(또는 "증가/급증")이다.
3. **Given** 외교부 공지가 8주 동안 50건을 넘는 활발한 시기, **When** 공지 템포를 계산하면, **Then** 오래된 주(week)가 목록 잘림 때문에 0건으로 집계되어 평시가 과소평가되는 일이 없다.
4. **Given** "최근 72시간" 사건 로그, **When** 화면에 표시되면, **Then** 72시간보다 오래된 사건은 목록에 없다(이전 값을 이어받은 경우 포함).
5. **Given** 실험적 "홍해 상공 회피" 지표, **When** 평시를 계산하면, **Then** 같은 시간대(hour-of-day)의 과거 값과 비교하여 밤/낮 항공편 차이가 "감소"로 오인되지 않는다.

### User Story 2 - 한 소스가 죽어도 대시보드가 죽지 않는다 (Priority: P1)

교민 사용자는 Google News RSS가 이상한 항목을 하나 보내거나 PortWatch가 빈 응답을 돌려줘도, 나머지 지표는 정상적으로 갱신된 화면을 보고 싶다. 코드 docstring이 이미 "실패한 소스는 이전 성공 데이터를 유지"라고 약속하고 있다.

**Why this priority**: 감사 결과 그 약속은 "예상한 예외 타입"에만 유효하다. `fetch_events`는 `RequestException`만 잡고, RSS item에 `<title>`이 없으면 `AttributeError`로 스크립트 전체가 죽어 그 시간의 커밋 자체가 사라진다(전 소스 손실). `fetch_maritime`은 PortWatch가 7일 미만 행을 주면 `IndexError`. 또 매시간 후티 메시지 6건을 매번 새로 번역해 MyMemory 무료 일일 한도에 의존하고 있고, 워크플로우는 `git push` 전 `pull --rebase`가 없어 사람 커밋과 겹치면 실패한다.

**Independent Test**: 소스 하나의 URL을 잘못된 주소로 바꿔 실행했을 때 스크립트가 0으로 종료하고, 그 소스만 `stale: true`, 나머지는 `ok: true`인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 어느 한 fetch 함수가 예상치 못한 예외(AttributeError, IndexError, TypeError 등)를 던짐, **When** `main()`이 실행되면, **Then** 해당 소스만 실패 처리(stale/이전 값 유지)되고 나머지 소스와 `data/latest.json` 저장은 정상 완료된다.
2. **Given** 직전 실행에서 이미 번역된 후티 메시지, **When** 다음 실행에서 같은 메시지(url 동일)를 다시 만나면, **Then** 번역 API를 다시 호출하지 않고 이전 `text_ko`를 재사용한다.
3. **Given** 봇이 push하기 직전에 사람이 main에 push한 상태, **When** 워크플로우가 커밋을 push하면, **Then** rebase 후 push되어 실행이 실패하지 않는다.
4. **Given** 외부 소스가 응답을 멈춤, **When** 워크플로우가 실행되면, **Then** 정해진 시간(15분) 안에 종료되고 6시간짜리 기본 타임아웃까지 매달리지 않는다.

### User Story 3 - 교민 가족이 오해 없이 읽는다 (Priority: P2)

한국에 있는 가족이 이 페이지를 열었을 때, "(이전 값)"이 1시간 전인지 3일 전인지, "마지막 업데이트" 시각이 한국 시간인지 사우디 시간인지, "수집 실패: HTTPSConnectionPool(...)"이 무슨 뜻인지 고민하지 않아야 한다.

**Why this priority**: 배지 정확성(US1)과 생존성(US2) 다음이지만, 매 방문마다 겪는 마찰이다. 감사에서 탭 제거 후 남은 죽은 문구("붉은 줄 = 선택한 권역")도 발견됐다.

**Independent Test**: 페이지를 헤드리스 브라우저로 열어 각 문구/라벨이 아래 시나리오와 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 어떤 소스가 stale 상태, **When** 타일에 표시되면, **Then** "(이전 값)" 대신 "(N시간 전 값)" 처럼 마지막 성공 시각으로부터의 경과가 보인다.
2. **Given** 수집 실패로 이전 값조차 없는 소스, **When** 타일에 표시되면, **Then** 파이썬 예외 문자열이 아니라 짧은 한국어 안내("수집 실패 — 다음 갱신 때 재시도")가 보이고, 원인은 마우스 오버(title)로만 노출된다.
3. **Given** "마지막 업데이트" 표시, **When** 어느 시간대의 브라우저로 열어도, **Then** 어느 시간대 기준인지 명시된다(페이지의 다른 시각 표기와 통일).
4. **Given** 페이지 본문, **When** 문구를 읽으면, **Then** 제거된 권역 탭을 전제로 한 문구("선택한 권역", "이 세 지표")가 없다.
5. **Given** 외교부 경보 한 줄, **When** 전국이 같은 기본 단계일 때, **Then** "나머지 특별여행주의보"가 권역마다 반복되지 않고 한 번만 나온다.
6. **Given** 지도 초기 화면, **When** 페이지를 열면, **Then** 지잔·아브하 등 남부 접경 도시 마커도 초기 뷰포트 안에 들어온다(지금은 그려지지만 화면 밖).
7. **Given** 중부(리야드) 권역의 "해상 교통" 타일, **When** 값을 읽으면, **Then** 호르무즈 해협이 리야드 로컬 신호가 아니라 전국 수출 회랑임이 타일에서 드러난다.

### User Story 4 - 문서가 현재 상태와 일치한다 (Priority: P3)

README와 코드 주석이 실제 동작(매시간 갱신, 탭 없음, FlightRadar24 실험 중)과 어긋나지 않아야 한다.

**Why this priority**: 사용자 영향은 없지만, 다음 세션의 Claude나 미래의 본인이 README를 믿고 잘못된 판단을 하게 된다. README "시도했지만 버린 것"에 "FlightRadar24는 봇 차단"이라고 적혀 있는데 지금 그 소스를 실험 중이다.

**Acceptance Scenarios**:

1. **Given** README, **When** 읽으면, **Then** "선택 권역", "권역 지도: 선택 권역만" 등 탭 전제 서술이 없고, FlightRadar24는 "실험 중" 항목으로 기술되며 "봇 차단" 항목과 모순되지 않는다.

### Edge Cases

- FIRMS 롤링 24시간 창을 쓰면 위성 패스 직후/직전에 값이 출렁일 수 있다 — 평시도 일별 중앙값이므로 비율은 여전히 비교 가능하나, 이 특성을 도움말에 한 줄 적는다.
- 번역 캐시는 메시지 url 기준이다. 채널이 메시지를 편집하면 원문이 바뀌어도 이전 번역이 남는다 — 원문 해시가 다르면 재번역하도록 한다.
- 워크플로우 `pull --rebase`가 충돌하면(사람이 `data/latest.json`을 직접 고친 경우) 봇 값을 우선하고 실패하지 않게 한다(`-X theirs`).

## Requirements *(mandatory)*

### Functional Requirements

**정확성**

- **FR-001**: 위성 열 감지 "최근 24h"는 현재 시각 기준 지난 24시간의 화점 수여야 한다(`acq_date`+`acq_time` UTC 기준). 상시 플레어 제외 건수도 같은 창을 쓴다.
- **FR-002**: 높을수록 위험한 지표(위성 열 감지, 공지 템포)의 비율 계산은 평시에 하한(floor)을 두어, 평시가 0 또는 극소값일 때 큰 현재값이 "평시"로 표시되는 일이 없어야 한다.
- **FR-003**: 외교부 공지 목록은 8주 창을 모두 덮을 만큼 가져와야 한다(최소 100건 또는 8주 전 날짜에 도달할 때까지).
- **FR-004**: 사건 로그와 지도 사건 마커는 클라이언트에서 72시간 창으로 걸러야 하며, 이전 값(stale)을 이어받았을 때도 같은 규칙을 적용한다.
- **FR-005**: "홍해 상공 회피"의 평시는 같은 시간대(UTC hour) 과거 값의 중앙값이어야 하고, 도움말 문구는 실제 갱신 주기(매시간)와 일치해야 한다. `maxage`는 "현재 상공"이라 부를 수 있는 범위(15분 이내)로 줄인다.

**견고성**

- **FR-006**: `main()`은 각 소스 fetch를 포괄적 예외 가드로 감싸, 어떤 예외가 나도 그 소스만 실패 처리하고 나머지 소스 수집과 파일 저장을 완료해야 한다. 실패 원인은 해당 소스의 `error`에 기록한다.
- **FR-007**: 각 소스는 마지막 성공 시각(`last_ok_at`)을 유지해야 하며, stale 상태로 이어받을 때 이 값이 보존되어야 한다.
- **FR-008**: 후티 메시지 번역은 (url, 원문 해시)가 같으면 이전 실행의 `text_ko`를 재사용해야 한다.
- **FR-009**: 워크플로우는 push 전에 `git pull --rebase`를 수행하고, job에 `timeout-minutes`를 둔다.
- **FR-010**: 실험적 소스(flights)도 다른 소스와 같은 재시도 헬퍼(`get()`)를 사용한다.

**명확성**

- **FR-011**: stale 표시는 마지막 성공 시각으로부터의 경과("N시간 전 값" / "N일 전 값")를 보여야 한다.
- **FR-012**: 수집 실패 시 타일 본문에는 짧은 한국어 안내만 보이고, 원시 오류 문자열은 `title` 속성으로만 제공한다.
- **FR-013**: "마지막 업데이트"는 시간대를 명시한다. 페이지의 사건·채널 시각이 사우디 현지시각이므로 동일하게 사우디 현지시각으로 표기하고 "(사우디 현지)"를 붙인다.
- **FR-014**: 권역 탭 제거를 반영하지 못한 문구를 모두 정리한다(`index.html` "붉은 줄 = 선택한 권역", "이 세 지표", README "선택 권역").
- **FR-015**: 외교부 경보 한 줄은 3단계(출국권고) 이상 지명만 권역별로 나열하고, 그 외 지역의 기본 단계는 전국 공통으로 한 번만 표기한다.
- **FR-016**: 지도 초기 뷰포트는 권역 box와 모든 도시 마커 좌표를 포함해야 한다.
- **FR-017**: 중부 권역의 해상 교통 타일 제목은 "해상 교통 · 호르무즈(전국 수출 회랑)"처럼 로컬 신호가 아님을 드러내야 한다.
- **FR-018**: 외부 URL을 `href`에 넣을 때는 텍스트와 동일하게 이스케이프한다.

**문서**

- **FR-019**: README를 현재 동작(탭 없음, 매시간, FlightRadar24 실험 중)에 맞게 갱신한다.

### Key Entities

- **Source Result**: 각 소스의 결과 블록. 속성: `ok`, `error`, `fetched_at`, **`last_ok_at`(신규)**, `stale`, 소스별 필드.
- **Translation Cache**: 이전 실행의 telegram 메시지 `(url, 원문 해시) → text_ko`. 별도 파일 없이 `previous`에서 읽는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 검증 스크립트(quickstart.md)가 `last24h ≤ 지난 24시간 acq 타임스탬프 화점 수`, `baseline floor` 적용, `events` 모두 72시간 이내를 모두 통과한다.
- **SC-002**: 소스 URL 하나를 고의로 깨뜨려 실행해도 exit code 0, 해당 소스 `stale: true` + `last_ok_at` 보존, 나머지 `ok: true`.
- **SC-003**: 같은 메시지 세트로 두 번 연속 실행했을 때 두 번째 실행의 번역 API 호출 수가 0이다.
- **SC-004**: 페이지 전체 텍스트에 "선택한 권역", "이 세 지표", 파이썬 예외 문자열 패턴(`Error`, `Pool`, `Traceback`)이 없다.
- **SC-005**: 워크플로우 파일에 `pull --rebase`와 `timeout-minutes`가 있고, 실제 Actions 실행 1회가 성공한다.

## Assumptions

- 갱신 주기는 매시간(`7 * * * *`)이며 001 문서의 "6시간"은 과거 상태다. 001 문서는 이력으로 남기고 수정하지 않는다.
- PortWatch의 최근 일자가 체계적으로 과소 집계되는 lag 아티팩트는 감사에서 발견되지 않았다(research.md). 따라서 해상 교통 계산 로직은 손대지 않는다.
- 저장소 용량(매시간 115KB 커밋), CDN SRI, FIRMS confidence 필터링은 품질 영향이 작아 이번 범위에서 제외한다(research.md "하지 않기로 한 것").
