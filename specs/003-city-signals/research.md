# Phase 0 Research: 도시 단위 재편 · 뉴스 파생 신호

2026-09-17 실측. 추측은 "확인 안 됨"으로 표시.

## 1. 사건 이력을 14일치로 미리 채울 수 있나 → 국문만 부분적으로

- **실측**: Google News RSS는 쿼리당 최대 100건. 영문 사건 쿼리를 `when:14d`로 바꿔도 100건이 전부 최근 ~1일(09-16~17)이라 허용 매체 27건·분류 사건 4건, 날짜 1개. 국문은 100건이 9일에 걸쳐 분류 사건 27건(09-12: 4, 09-14: 1, 09-15: 8, 09-16: 14).
- **Decision**: 이력은 **매시간 누적**이 본체. 최초 1회 `EVENT_DAYS=14` 시드는 국문 쪽 공백을 줄이는 보조. "이전 7일 대비"는 이력 14일 미만이면 표시하지 않고 "이력 N일째"로 쓴다(FR-017). 스펙의 "없는 비교를 0으로 꾸미지 않는다" 원칙과 일치.
- **Alternatives**: 날짜 구간을 쪼개 여러 번 질의(`after:`/`before:`) — Google News RSS가 `after:`를 지원하긴 하나 허용 매체 필터 후 건수가 적고, 이 대시보드의 사건 정의(허용 매체 + 도시 + 유형)를 과거로 소급하는 이득이 2주 뒤면 사라진다. 기각.

## 2. 후티 채널 이력 → 누적 필요, 크기 문제 없음

- **실측**: `t.me/s/army21ye` 미리보기 1페이지 = 18건, 약 24시간 분량(09-15 17:31 ~ 09-16 17:55). 하루 ~18건을 올리는 채널.
- **영향**: 7일 언급 집계는 한 번의 수집으로 불가능 → 매시간 수집분을 url 기준으로 누적. 사우디 언급 필터를 통과하는 건 하루 3~6건이라 14일 ≈ 60건 × ~1KB ≈ 60KB.
- **Decision**: 필터 통과 메시지만 14일 누적. 번역은 표시되는 최신 6건 중 `text_ko` 없는 것만(이력 자체가 캐시). 채널이 삭제한 메시지도 이력엔 남긴다 — 발표 사실이 신호.

## 3. 도시 현황표 vs 도시별 카드

- **Decision**: 표 하나.
- **Rationale**: 추적 도시가 20곳. 카드 20장은 권역 타일 6장보다 더 나쁜 "그럴싸한 그리드"가 된다. 표는 정렬 규칙 하나로 "지금 어디가 문제인가"를 위에 올릴 수 있고, 모바일에서 열만 접으면 된다. 사용자의 지적("세그먼트를 세 개로 나누지 마")은 중간 분류를 없애라는 것이지 카드를 늘리라는 것이 아니다.
- **Alternatives**: 상위 5개 도시만 카드 + 나머지 표 — 두 UI를 유지해야 하고 "왜 내 도시는 카드가 아니냐"가 생긴다. 기각.

## 4. 사건 템포·언급 집계를 어디서 계산하나 → 수집 스크립트

- **Decision**: 파이썬에서 `tempo`, `mentions7d`, `changes`를 계산해 JSON에 넣고, 프론트는 렌더만.
- **Rationale**: quickstart의 불변식 검사가 "JSON의 표 숫자 == 이력을 직접 센 값"으로 단순해지고, 창(7일)의 날짜 기준(사우디 현지 `date`)을 한 곳에서만 정의한다. 프론트에서 하면 브라우저 시간대에 따라 창이 흔들린다.

## 5. FAA NOTAM API — 응답 구조는 키 수령 후 확정 (확인 안 됨)

- **확인됨**: 엔드포인트 `https://external-api.faa.gov/notamapi/v1/notams`가 살아 있고 키 없이는 `401 {"message":"Unauthorized"}`. 인증은 헤더 `client_id`/`client_secret`(FAA 포털 가이드 PDF §7). 포털: `api.faa.gov` → `portal.apic4e.faa.gov`, "Production Manual Approval" 티어 분당 50건.
- **확인 안 됨**: 응답 JSON의 정확한 필드 경로. 공개 문서·클라이언트 라이브러리 기준으로 `items[].properties.coreNOTAMData.notam.{number, effectiveStart, effectiveEnd, text, location, classification}`가 일반적이나, 첫 실제 응답으로 확정한다. 코드는 `.get()` 체인으로 방어하고 `safe()` 가드가 최악을 막는다.
- **분류 키워드**: 공역 폐쇄·제한·위험구역·미사일/로켓/사격·UAS·GPS 간섭. Q코드가 텍스트에 포함되면 `QRTCA/QRDCA/QRPCA/QRRCA`도 매치에 추가.
- **대상**: OEJN(제다) OERK(리야드) OEDF(담맘) OEMA(메디나) OEJD(사우디 FIR — 공역 전체 NOTAM은 FIR 단위로 나온다).
- **Decision**: 비밀값 없으면 `enabled: false`로 완전 비활성. FAA가 거절하면 이 상태로 영구히 남고 아무 영향이 없다.

## 6. 헤드라인에 무엇을 남기나

- **Decision**: ① 출국권고 도시 나열 + 그 외 기본 단계 ② 최근 30일 단계 변경(최대 3건) ③ 이번 주 공지 건수(평시 대비).
- **Rationale**: 셋 다 외교부 발이라 신뢰도가 같고, 사용자 기준으로 "숫자 한 줄"까지는 정보, 그래프는 장식. 공지 템포의 `tier`(급증/증가/평시) 단어는 유지하되 배지가 아니라 문장 속 단어로.

## 7. 지도에서 항만 팝업 제거

- **Decision**: PortWatch를 수집 자체에서 제거하므로 팝업의 "7일 입항"도 사라진다. 팝업은 도시명·단계·최근 7일 사건 수만.
- **Rationale**: 5일 지연 데이터를 팝업에만 남기면 "숨은 그럴싸함"이 된다. 일관되게 뺀다.
