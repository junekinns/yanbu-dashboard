# Feature Specification: 도시 단위 재편 · 뉴스 파생 신호 중심으로

**Feature Branch**: `003-city-signals` (main에 직접 반영 — 001·002와 동일)

**Created**: 2026-09-17

**Status**: Draft

**Input**: User description: "대시보드를 '그럴싸해 보이는 것'에서 '실제로 유용한 것'으로 재편. 1) 방문자에게 GitHub 로그인이 필요한 '지금 바로 데이터 재수집' 링크 제거. 2) 서부/중부/동부 3분할을 없애고 도시 단위로 재편. 3) 해상 교통 타일 제거, 위성 열 감지는 지도 화점 레이어로만 유지. 4) 뉴스·후티 채널·외교부에서 파생 신호를 만들어 중심에 둔다: (a) 도시별 사건 템포, (b) 외교부 경보 단계 변경 감지, (c) 후티 채널 표적 언급 순위. 5) FAA NOTAM은 키를 받으면 GitHub Secrets로 넣어 추가하는 선택 항목. 새 파일·새 의존성 없이."

**사용자의 원 지적** (설계 기준으로 삼는다): "위성감지와 해상교통은 그래프로 그럴싸해 보이긴 하지만 자주 변하는 것도 아니고, 실질적인 유용한 정보는 다 뉴스인데? 그럴싸해 보이는 척 말고."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 도시 한 줄로 "내가 있는 곳" 상황을 읽는다 (Priority: P1)

얀부에 사는 부모님, 다란에 다니는 가족, 한국에서 걱정하는 배우자가 페이지를 열면, 자기 도시 한 줄에서 **외교부 단계 · 이번 주 사건 수(지난주 대비) · 후티가 이 도시를 지목한 횟수**를 바로 본다. 서부/중부/동부 같은 중간 분류를 거치지 않는다.

**Why this priority**: 이것이 재편의 본체다. 지금 화면은 권역 3개 × 지표 2개의 그래프 타일인데, 그래프는 며칠에 한 번 바뀌고 사용자는 "우리 동네"를 찾으려면 권역 이름을 먼저 해석해야 한다.

**Independent Test**: 페이지를 열어 도시 현황표에 얀부·제다·리야드·담맘·다란·주베일·지잔·아브하·나즈란·카미스무샤이트 등 추적 도시가 각각 한 줄로 있고, 각 줄에 단계·7일 사건 수·지난주 대비·후티 언급이 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 대시보드 첫 로드, **When** 상단을 보면, **Then** 권역 탭·권역 그리드·권역 배지 없이 도시 현황표가 보이고, 각 줄은 도시명 / 외교부 단계 / 최근 7일 사건 수(유형별) / 이전 7일 대비 증감 / 최근 7일 후티 언급 횟수를 담는다.
2. **Given** 도시 현황표, **When** 정렬을 보면, **Then** 외교부 단계가 높은 도시, 그 다음 최근 7일 사건이 많은 도시 순으로 위에 온다.
3. **Given** 어떤 도시에 최근 7일 사건이 0건, **When** 그 줄을 보면, **Then** "0"이 아니라 "—"처럼 조용함이 시각적으로 구분되고 붉은 강조가 없다.
4. **Given** 화면 폭이 좁은 휴대폰, **When** 표를 보면, **Then** 가로 스크롤 없이 도시명과 단계·사건 수가 읽힌다.

### User Story 2 - "언제 뭐가 바뀌었나"를 놓치지 않는다 (Priority: P1)

교민에게 가장 실질적인 사건은 외교부가 자기 도시의 단계를 올리거나 내리는 것이다. 지금은 현재 단계만 보여서, 어제 제다가 특별여행주의보에서 출국권고로 바뀌었는지 알 수 없다.

**Why this priority**: 파생 신호 세 개 중 가장 행동과 직결된다(출국권고 = 떠나라). 데이터는 이미 매시간 수집하고 있어 이력만 남기면 된다.

**Independent Test**: 수집 이력에 단계 변경이 있는 상태로 페이지를 열어, 상단 헤드라인과 도시 줄에 "제다 특별여행주의보 → 출국권고 (9/16)" 형태로 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 이전 수집 대비 어떤 도시의 외교부 단계가 달라짐, **When** 다음 수집 후 페이지를 열면, **Then** 상단 헤드라인에 "최근 변경: 제다 특별여행주의보 → 출국권고 (9/16)"가 보이고 해당 도시 줄에도 변경 표시가 붙는다.
2. **Given** 최근 30일 변경이 없음, **When** 헤드라인을 보면, **Then** "최근 30일 단계 변경 없음 (추적 시작 YYYY-MM-DD)"이 보인다.
3. **Given** 외교부 수집이 실패한 실행, **When** 단계 비교를 하면, **Then** 실패를 "단계 없음"으로 오인해 가짜 변경을 만들지 않는다.

---

### User Story 3 - 후티가 어디를 지목하는지 본다 (Priority: P2)

후티 군 대변인 채널은 공격을 발표할 때 도시를 지명한다. 최근 7일 언급 횟수 순위는 이 대시보드만 가진 선행 신호다. 지금은 메시지 6건을 나열만 하고 있다.

**Why this priority**: 뉴스보다 앞서는 유일한 소스지만 상대측 발표라 검증되지 않았음을 늘 붙여야 하므로 P2.

**Independent Test**: 최근 7일 메시지에서 도시 언급을 집계해 "카미스무샤이트 4 · 얀부 2 · 제다 1" 형태의 순위가 표시되고, 도시 현황표의 후티 열과 숫자가 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 최근 7일 후티 메시지들, **When** 후티 채널 섹션을 보면, **Then** 메시지 목록 위에 "최근 7일 언급 표적" 순위(도시·횟수)가 있고 "상대측 발표, 검증되지 않음" 문구가 함께 있다.
2. **Given** 한 메시지가 같은 도시를 여러 번 언급, **When** 집계하면, **Then** 메시지당 1회로 센다(문장 반복으로 부풀지 않게).
3. **Given** 7일 동안 사우디 도시 언급이 없음, **When** 섹션을 보면, **Then** "최근 7일 사우디 도시 언급 없음"이 보인다.

---

### User Story 4 - 사건 템포를 도시별로 비교한다 (Priority: P2)

"얀부 이번 주 피격 1건 · 경보 0건 (지난주 0건)"처럼 사용자가 신뢰하는 뉴스에서 나온 숫자로 추세를 읽는다. 지금 사건 로그는 72시간 나열뿐이라 "지난주보다 심해졌나"를 알 수 없다.

**Why this priority**: US1 표의 핵심 열이지만, 이력을 2주 이상 쌓아야 "지난주 대비"가 의미를 갖는다. 표 자체(US1)는 이력이 짧아도 동작한다.

**Independent Test**: 사건 이력이 14일 이상 쌓인 상태에서 도시 줄의 "7일 vs 이전 7일" 숫자가 이력의 실제 건수와 일치하는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 매시간 수집된 사건, **When** 이력을 보면, **Then** 같은 사건(날짜·도시·유형)은 한 번만 저장되고 최소 30일 보관된다.
2. **Given** 이력이 14일 미만, **When** 도시 줄을 보면, **Then** "이전 7일" 비교 대신 "이력 N일째"가 보인다(없는 비교를 0으로 꾸미지 않는다).
3. **Given** 지도, **When** 기간 토글(24h/72h/7일)을 바꾸면, **Then** 사건 마커가 이력 기준으로 7일까지 실제로 채워진다(지금은 3일치만 있음).

---

### User Story 5 - 그럴싸하기만 한 것을 걷어낸다 (Priority: P1)

방문자 화면에서 GitHub 로그인 링크, 권역 3분할, 해상 교통 타일, 위성 열 감지 타일·그래프, 공지 템포 그래프가 사라진다. 위성 화점은 지도 레이어로, 공지 건수는 헤드라인의 숫자 하나로 남는다.

**Why this priority**: 제거는 비용이 거의 없고, 남는 화면이 US1~4의 자리를 만든다. 로그인 링크는 방문자에게 노출되면 안 되는 것이라 즉시.

**Independent Test**: 페이지 전체 텍스트에 "GitHub 로그인", "서부"/"중부"/"동부" 권역 라벨, "해상 교통", "공지 템포" 타일이 없고, 지도 범례에 "위성 이상 화점"은 남아 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 페이지 상단, **When** 새로고침 영역을 보면, **Then** "↻ 새로고침" 버튼만 있고 GitHub 로그인이 필요한 링크가 없다.
2. **Given** 지도, **When** 범례를 보면, **Then** 위성 이상 화점 레이어와 최근 N시간 화점 수는 그대로 있다.
3. **Given** 헤드라인, **When** 읽으면, **Then** "이번 주 외교부 공지 7건 (평시 1.5건)"처럼 공지 템포가 숫자 한 줄로 남는다.

---

### User Story 6 - (선택) 사우디 공역 폐쇄 통보를 본다 (Priority: P3)

사용자가 FAA NOTAM API 자격증명을 받아 저장소 비밀값으로 넣으면, 제다·리야드·담맘·메디나 공항과 사우디 비행정보구역의 현행 공역 제한 NOTAM이 섹션으로 나타난다. 비밀값이 없으면 섹션 자체가 없다.

**Why this priority**: 공역 폐쇄는 공식 경보보다 앞서는 진짜 선행 신호지만, 자격증명 발급이 FAA 수동 승인이라 언제 될지 모른다. 없어도 완결된 기능이어야 한다.

**Independent Test**: 비밀값 없이 실행 → 섹션 없음·오류 없음. 비밀값 있음 → 섹션에 NOTAM 건수와 목록.

**Acceptance Scenarios**:

1. **Given** 자격증명 미설정, **When** 수집·페이지 로드하면, **Then** NOTAM 관련 UI가 전혀 없고 수집 로그에도 실패로 찍히지 않는다("비활성").
2. **Given** 자격증명 설정, **When** 수집하면, **Then** 대상 공항·FIR별 현행 NOTAM 중 공역 제한·폐쇄 성격의 항목 수와 원문 요약이 표시된다.
3. **Given** 자격증명은 있으나 API 거부(만료·한도), **When** 수집하면, **Then** 다른 소스와 같은 방식으로 이전 값 유지·"N시간 전 값" 표시.

### Edge Cases

- 도시 매칭이 안 되는 사건(예: "송유관")과 후티의 "사우디" 일반 언급은 도시 표에 넣지 않고 사건 로그/메시지 목록에만 둔다. 표는 도시 단위라는 정의를 지킨다.
- 외교부 페이지 구조 변경으로 단계 파싱이 실패하면 그 실행은 이전 단계를 유지하고 변경 감지를 건너뛴다(US2 시나리오 3).
- 사건 이력 누적 초기(첫 2주)에는 "지난주 대비"를 표시하지 않는다(US4 시나리오 2). 최초 1회는 14일 범위 뉴스 검색으로 이력을 미리 채워 공백을 줄인다.
- 후티 메시지 이력은 채널 웹 미리보기가 최근 20건 정도만 노출하므로 매시간 수집분을 누적해 7일을 만든다. 채널이 메시지를 삭제해도 이력엔 남는다(발표 사실 자체가 신호).
- 도시 현황표 정렬에서 단계가 같고 사건도 같은 도시는 가나다순으로 안정 정렬한다(매 갱신마다 줄이 뒤바뀌지 않게).

## Requirements *(mandatory)*

### Functional Requirements

**제거 (US5)**

- **FR-001**: 방문자 화면에서 GitHub 로그인이 필요한 수동 재수집 링크를 제거한다. 캐시 무시 새로고침 버튼은 유지한다.
- **FR-002**: 서부/중부/동부 권역 개념을 화면에서 제거한다(권역 헤딩·권역별 타일 그리드·권역 배지). 수집 데이터의 지도 초기 범위 계산에만 남길 수 있다.
- **FR-003**: 해상 교통(항만·해협 통과량) 수집과 표시를 제거한다.
- **FR-004**: 위성 열 감지의 타일·그래프·평시 계산을 제거하고, 지도 화점 레이어(상시 플레어 제외)와 범례 건수만 유지한다.
- **FR-005**: 공지 템포 타일·그래프를 제거하고, 이번 주 건수와 평시를 헤드라인 문장 하나로 표시한다.

**도시 현황표 (US1)**

- **FR-006**: 추적 도시 목록(외교부 단계 매핑이 있는 지점 전체, 좌표 없는 항목 제외)을 표 한 개로 보여준다. 열: 도시 / 외교부 단계 / 최근 7일 사건(경보·요격·피격·공습 건수) / 이전 7일 대비 / 최근 7일 후티 언급.
- **FR-007**: 정렬은 외교부 단계 내림차순 → 최근 7일 사건 수 내림차순 → 도시명 가나다순.
- **FR-008**: 0건은 "—"로, 사건이 있는 칸만 강조한다. 단계 변경이 있는 도시는 변경 표시를 붙인다.
- **FR-009**: 도시명을 누르면 지도가 그 도시로 이동하고 팝업이 열린다(표와 지도를 잇는 유일한 상호작용).

**외교부 단계 변경 (US2)**

- **FR-010**: 매 수집마다 도시별 단계를 이전 값과 비교해, 달라진 경우 (도시, 이전 단계, 새 단계, 감지 일시)를 변경 이력에 추가한다. 이력은 최소 90일 보관한다.
- **FR-011**: 외교부 수집이 실패한 실행에서는 비교를 수행하지 않는다.
- **FR-012**: 헤드라인에 최근 30일 변경을 최신순으로 최대 3건 표시하고, 없으면 "최근 30일 단계 변경 없음 (추적 시작 날짜)"를 표시한다.

**후티 표적 언급 (US3)**

- **FR-013**: 후티 채널 메시지를 누적 보관한다(최소 14일, 메시지 링크 기준 중복 제거).
- **FR-014**: 최근 7일 메시지에서 도시 언급을 메시지당 1회로 집계해 순위(도시·횟수)를 만들고, 후티 채널 섹션 상단과 도시 현황표의 후티 열에 표시한다.
- **FR-015**: 순위 옆에 "상대측 발표 · 검증되지 않음" 문구를 항상 붙인다.

**사건 템포 (US4)**

- **FR-016**: 사건을 누적 보관한다(최소 30일, (날짜·도시·유형) 기준 중복 제거, 같은 사건의 매체 수는 최대값으로 갱신).
- **FR-017**: 도시별 최근 7일·이전 7일 건수를 유형별로 계산한다. 이력이 14일 미만이면 "이전 7일"은 계산하지 않고 이력 일수를 표시한다.
- **FR-018**: 최초 배포 시 1회 14일 범위 검색으로 이력을 미리 채운다. 이후 매시간 수집은 3일 범위를 유지한다.
- **FR-019**: 사건 로그(72시간)와 지도 마커(24h/72h/7일)는 누적 이력에서 읽는다.

**NOTAM 선택 항목 (US6)**

- **FR-020**: 저장소 비밀값에 FAA 자격증명이 있을 때만 NOTAM 수집이 활성화된다. 없으면 수집을 시도하지 않고 데이터에 "비활성" 상태만 남기며, 화면에 섹션을 만들지 않는다.
- **FR-021**: 활성 시 제다(OEJN)·리야드(OERK)·담맘(OEDF)·메디나(OEMA)와 사우디 FIR(OEJD)의 현행 NOTAM 중 공역 제한·폐쇄 성격(공역 폐쇄, 활동 제한, 위험구역 활성)을 골라 건수와 요약을 표시한다.
- **FR-022**: 자격증명은 화면·저장소 파일 어디에도 기록되지 않는다.

**공통**

- **FR-023**: 새 파일·새 외부 의존성 없이 기존 수집 스크립트·페이지·스타일 안에서 구현한다. 그레이스풀 디그레이드(이전 값 유지, "N시간 전 값")는 새 파생 데이터에도 동일하게 적용한다.
- **FR-024**: README와 페이지 도움말을 재편 후 상태에 맞게 갱신한다(지표 목록, 제거 사유, 파생 신호 정의).

### Key Entities

- **City Status Row**: 도시명, 좌표, 외교부 단계(현재), 최근 변경(있으면), 7일 사건 건수(유형별), 이전 7일 건수(유형별, 이력 충분할 때), 7일 후티 언급 수.
- **Advisory Change**: 도시, 이전 단계, 새 단계, 감지 일시. 이력으로 누적.
- **Event History Entry**: 날짜(현지), 도시, 유형, 최초 보도 시각, 대표 제목·링크·매체, 매체 수. (날짜·도시·유형)이 키.
- **Houthi Message History Entry**: 메시지 링크(키), 시각, 언급 도시 목록, 원문, 번역.
- **NOTAM Entry (선택)**: 대상(공항/FIR), 식별자, 유효 기간, 분류(공역 폐쇄/제한/위험구역), 원문 요약.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 얀부 거주자가 페이지를 열어 스크롤 없이 "얀부" 줄을 찾고 단계·이번 주 사건 수·후티 언급을 읽는 데 10초 이내.
- **SC-002**: 페이지 전체 텍스트에 "GitHub 로그인", 권역 라벨(서부/중부/동부), "해상 교통", "공지 템포" 타일이 0건. 지도 범례의 "위성 이상 화점"은 유지.
- **SC-003**: 외교부 단계가 실제로 바뀐 뒤 다음 수집(최대 1시간) 안에 헤드라인과 도시 줄에 변경이 나타난다.
- **SC-004**: 도시 현황표의 7일 사건 수·후티 언급 수가 각각 사건 이력·메시지 이력을 직접 세어 얻은 값과 100% 일치한다.
- **SC-005**: 사건 이력이 14일 이상 쌓인 뒤 "이전 7일 대비"가 모든 추적 도시에 대해 계산되며, 그 전에는 어떤 도시도 가짜 "0 → N" 비교를 보여주지 않는다.
- **SC-006**: FAA 자격증명이 없는 상태에서 수집·페이지 로드에 NOTAM 관련 오류·빈 섹션이 0건.
- **SC-007**: 기존 자동 갱신 실행 시간이 재편 전(약 30초)보다 늘지 않는다(해상 교통 제거로 줄어드는 것이 기대값).

## Assumptions

- 도시 현황표의 추적 도시는 기존 지점 목록(외교부 단계 매핑 대상 20곳 중 좌표 있는 곳) 전체를 쓴다. 특정 도시를 고정 상단에 두는 개인화는 하지 않는다(정렬 규칙으로 충분하다고 가정).
- "홍해 상공 회피" 실험 지표는 이번 재편 대상이 아니다(같은 시각 평시가 아직 쌓이는 중이라 판단을 미룬다). 화면 하단 실험 영역에 그대로 둔다.
- 해상 교통 제거로 지도 도시 팝업의 "7일 입항" 정보도 함께 사라진다. 사용자 지적(5일 지연)이 팝업에도 동일하게 적용된다고 본다.
- 사건 이력의 "이전 7일 대비"가 의미를 가지려면 2주가 필요하다. 그 전에는 이력 일수를 표시하는 것이 정직한 상태라고 합의된 것으로 본다(사용자의 "그럴싸한 척 말고" 기준).
- FAA 자격증명은 사용자가 직접 저장소 비밀값으로 넣는다. 승인이 거절되면 US6은 영구 비활성 상태로 남으며 다른 기능에 영향이 없다.
- 후티 채널 메시지에서 도시를 뽑는 기존 아랍어·영어 지명 사전을 그대로 쓴다. 새 도시 추가는 범위 밖.
