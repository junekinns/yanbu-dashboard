**Created**: 2026-09-16

**Status**: In Progress

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 숨은 신호 전수조사 (Priority: P1)

교민 사용자가 대시보드를 열었을 때, 이미 공개된 뉴스로 알 수 있는 정보의 재탕이 아니라 "아직 뉴스가 되기 전" 조짐을 알려주는 지표를 보고 싶어한다.

**Why this priority**: 이번 요청의 핵심 동기. 기존 4개 지표 중 상당수가 뉴스/공지의 사후 반영이라는 지적을 받음.

**Independent Test**: 각 후보 소스에 실제 요청을 보내 응답·데이터 존재 여부를 확인하고, 채택/기각 사유를 spec에 기록한다.

**Acceptance Scenarios**:

1. **Given** 후보 소스 목록, **When** 실제 API/페이지에 요청을 보내면, **Then** 각 소스의 접근 가능 여부와 신호 품질이 문서화된다.
2. **Given** 채택된 소스, **When** fetch_data.py에 통합하면, **Then** 로컬 실행에서 실제 값이 나온다.

---

### User Story 2 - 의미 없는 지표 정리 (Priority: P1)

사용자는 첫 화면에서 신호와 잡음을 구분하고 싶어하며, 근거가 약한 지표는 빼거나 격을 낮추길 원한다.

**Why this priority**: 반복적으로 "의미 없다", "과하다"는 피드백을 받음.

**Acceptance Scenarios**:

1. **Given** 현재 4개(과거 관심도 포함 이력) 지표, **When** 각각의 근거를 재검토하면, **Then** 유지/제거/격하 판단과 이유가 기록된다.

---

### User Story 3 - 후티 채널 한글 우선 표시 (Priority: P2)

사용자는 아랍어 원문을 먼저 읽고 번역 버튼을 누르는 두 단계를 거치고 싶지 않다.

**Independent Test**: 채널 메시지를 미리 한국어로 번역해 기본 표시하고, 원문은 접어서 제공한다.

**Acceptance Scenarios**:

1. **Given** 후티 채널의 새 메시지, **When** 대시보드에 표시되면, **Then** 한국어 번역이 기본으로 보이고 원문은 토글로 볼 수 있다.

---

### User Story 4 - 지도뷰 고도화 검토 (Priority: P2)

사용자는 Palantir AIP류의 실시간 미사일 궤적·3D·위성뷰가 가능한지 알고 싶어한다.

**Independent Test**: 각 후보 기술의 데이터 가용성과 비용/복잡도를 조사해 채택/기각을 문서화하고, 채택분만 구현한다.

**Acceptance Scenarios**:

1. **Given** 후보 지도 고도화 항목, **When** 실제 데이터 소스를 확인하면, **Then** 실현 가능한 것만 골라 구현하고 나머지는 기각 사유를 기록한다.

---

### User Story 5 - 수동 갱신 (Priority: P1)

사용자는 6시간을 기다리지 않고 필요할 때 즉시 최신 데이터를 보고 싶어한다.

**Independent Test**: GitHub Actions workflow_dispatch를 트리거하는 경로(문서화된 링크 또는 버튼)를 만들고, 실제로 눌러서 데이터가 갱신되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 정적 GitHub Pages 사이트, **When** 사용자가 수동 갱신을 요청하면, **Then** 별도 백엔드 없이 워크플로우가 트리거되고 결과가 사이트에 반영된다.

### Edge Cases

- 채택한 신규 소스가 나중에 막히면(차단/스펙 변경) 그레이스풀 디그레이드로 이전 값을 유지해야 한다.
- 수동 갱신은 GitHub 로그인이 필요한 방식이라, 로그인 없는 방문자(교민 가족)를 위한 대안(캐시 무효화 새로고침 등)도 함께 제공해야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 최소 5개 이상의 신규 후보 소스에 실제 네트워크 요청을 보내 가용성을 검증해야 한다.
- **FR-002**: 채택된 신규 소스는 기존 그레이스풀 디그레이드 패턴(ok/stale/error)을 따라야 한다.
- **FR-003**: 근거가 약하다고 판단된 기존 요소는 제거하거나 명확히 격하 표시해야 한다.
- **FR-004**: 후티 채널 메시지는 한국어 번역이 기본 노출, 아랍어 원문은 접힌 상태로 제공해야 한다.
- **FR-005**: 번역은 외부 번역 API 호출 실패 시에도(그레이스풀 디그레이드) 원문이라도 보여야 한다.
- **FR-006**: 지도는 기존 2D Leaflet 대비 최소 하나 이상의 실질적 개선(실시간 궤적, 위성 타일, 혹은 그에 준하는 것)을 포함하거나, 불가능하면 그 근거를 README에 남겨야 한다.
- **FR-007**: 수동 갱신 경로는 페이지 소유자(계정 보유자)뿐 아니라 대시보드 방문자(비로그인)도 "최신 상태 확인"에 준하는 행동을 할 수 있어야 한다(예: 캐시 무효화 강제 새로고침 버튼 + 로그인 사용자용 워크플로우 트리거 링크).

### Key Entities

- **Signal Source**: 개별 데이터 출처(API/스크래핑). 속성: 이름, 실시간성, 신뢰도, 채택 여부, 기각 사유.
- **Telegram Message**: 후티 채널 메시지. 속성: 원문(아랍어), 번역(한국어), 시각, 감지된 지명.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 최소 5개 신규 소스가 실제로 테스트되고 결과가 문서화된다.
- **SC-002**: 최종 대시보드의 각 지표에 대해 "왜 유의미한가"를 한 문장으로 설명할 수 있다.
- **SC-003**: 후티 채널 카드에서 사용자가 별도 클릭 없이 한국어 문장을 읽을 수 있다.
- **SC-004**: 사용자가 페이지에서 버튼 하나로 "최신 데이터 확인 시도"를 할 수 있다(수동 새로고침 fetch 또는 워크플로우 트리거 링크).

## Assumptions

- 실시간(초 단위) 미사일 추적은 군사 기밀 영역이라 민간 무료 소스로는 불가능하다고 가정하고, 조사 후 확정한다.
- 번역은 무료 공개 API(예: Google Translate 비공식 엔드포인트 또는 LibreTranslate)로 처리하며, 유료 API 키는 쓰지 않는다.
- GitHub Pages는 정적 호스팅이므로 "버튼 클릭 → 즉시 서버 재계산"은 불가능하고, 최선은 (a) 로그인 사용자의 워크플로우 수동 트리거, (b) 방문자의 브라우저 캐시 무효화 새로고침이다.
